## 4. Metronome enhancements
- [x] Update metronome so that it supports multiple time signatures.
  - Added a `beatsPerBar` variable (default 4, was hardcoded) and a `#timeSignature` `<select>` (2/4, 3/4, 4/4, 5/4, 6/8, 7/8, 9/8, 12/8) next to the existing subdivision control; each option's value is just the beat count, so 6/8 etc. are treated as "N clicks per bar" rather than modeling compound-meter beat groupings.
  - The `.beat` lights are now generated by `renderBeats()` instead of being 4 hardcoded divs in the HTML, so the row always matches the current `beatsPerBar`; `setTimeSignature()` updates `beatsPerBar`, resets `metroBeat` to 0, and re-renders them. `.beats` got `flex-wrap` so 9/8 or 12/8 don't overflow on narrow screens.
  - `metroClick()`'s bar-wrap (`% 4`) and `flashBeat()`'s `visualBeat` calc were both switched from the hardcoded `4` to `beatsPerBar`.

## 5. Responsive layout
- [x] Improve style responsiveness for different screen sizes (phone/tablet/desktop breakpoints).
  - `.app` is now a flex column; `.note`/`.center` sizes moved from fixed pixels to `cqw` units off a `container-type: inline-size` on `.circle`, so they scale fluidly with the circle instead of jumping at a single 500px breakpoint (with a `@supports not (container-type: inline-size)` fallback to the old fixed sizes for older browsers). Kept a few explicit breakpoints (`max-width: 600px`/`380px`) for button/select padding and font-size on phones.
- [x] Keep the whole UI visible within the viewport with no scrolling required — fit notes circle, controls, and metronome on screen at once, scaling/reflowing as needed.
  - Pure CSS (`vh`-based guesses) can't know how tall the metronome/controls actually render, so this is JS-measured instead: `fitLayout()` (called on load, on `resize`, and after `setTimeSignature()`) measures the rendered height of everything except the circle and sets `--circle-size` to whatever's left over, capped at 600px.
  - If a comfortable circle (≥180px) doesn't fit, it progressively adds `.compact` (hides `.hint`, tightens metronome padding) then `.ultra-compact` (also hides `.subtitle`/`.metro-title`) before shrinking the circle further, down to a 130px floor.
  - Split the markup into `.panel` (header/metronome/controls/status/hint) + `.circle` as the two direct children of `.app`, so short-and-wide windows (`max-height: 560px` and `min-width: 900px` — laptop windows shrunk short, not narrow phones in landscape, where a narrower panel just wraps taller and loses more than it gains) can switch to a row layout with the panel beside the circle instead of stacked above it.
  - Verified with headless Chrome across ~20 sizes (iPhone SE/12/14 portrait, common tablets, laptop/desktop resolutions, short/wide windows): all fit with zero overflow. Only very short landscape-phone heights (⪅330px `innerHeight`) still show a small residual overflow (`overflow-y: auto` on `body` is the fallback) — real mobile browsers report a taller `innerHeight` in landscape than the headless test harness did, so this is a synthetic worst case, not a real-device regression.
